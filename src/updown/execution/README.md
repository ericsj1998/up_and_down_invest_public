# `execution` — 집행 (spec §4.10)

**책임**: 진입 트리거 감시, 주문 제출·정정·취소, 체결 추적, 손절/익절 집행,
멱등키 관리, **`OrderGateway`**(브로커 어댑터 획득의 유일한 지점).

**하지 않는 것**: **판단**. 입력은 `ApprovedOrder` 이고 가격·수량은 이미 확정돼 있다(§4.10).
여기서 값을 조정하고 싶어지면 `decision` 이 정보를 덜 준 것이다 — 그쪽을 고친다.

**절대 규칙**:
- **#0 — 브로커 어댑터는 `OrderGateway.resolve_adapter()` 로만 얻는다.** 직접 생성·import 금지.
  `tests/test_gateway_bypass.py` 가 우회 코드 부재를 강제한다.
- **#6 — 모든 주문에 멱등키.** 재시도 전에 반드시 체결 여부를 먼저 조회한다 (§4.10, §7).
- **#8-1 — 로그 적재 실패가 리스크 감소 행동을 막지 않는다.** 손절·청산·스탑 상향·주문 취소는
  로그가 실패해도 무조건 집행하고 폴백 파일에 남긴다 (§1.2.1).

> **Phase 0~1**: PaperAdapter 가 아직 없으므로(P2-1) 게이트는 **어떤 조건에서도 실주문 어댑터를
> 반환하지 않고 예외를 던진다.** 이것이 "실주문 물리적 차단"의 실체다.
