# `orchestration` — 조립 계층 (spec §4.9, §4.11, §4.13, §4.20)

## 입주 조건 ⭐

> **자체 판단 로직이 없고, 여러 도메인을 호출만 하는 모듈**만 들어온다.
> 계산·판단이 생기는 순간 그 코드는 해당 도메인 패키지 소속이다.

이 한 줄이 `orchestration` 이 "아무거나 넣는 서랍"이 되는 것을 막는 **유일한 장치**다.
새 파일을 여기 두려 할 때마다 이 문장을 통과하는지 확인한다.

## 현재 입주 대상

| 모듈 | 스펙 | 입주 근거 (스펙 자신의 표현) |
|------|------|------------------------------|
| Backtest Engine | §4.11 | "**실거래와 동일한 전략 코드** 실행" — 세 도메인을 전부 호출 |
| Recommendation | §4.9 | "자체 분석 로직 없음. **순수 오케스트레이터**" |
| Instant Analysis | §4.20 | "새 분석 로직 없음, **기존 모듈 호출만**" |
| Charting 투영 | §4.13 | 분석 산출물을 차트 표현으로 변환만 |

## 왜 이 패키지가 필요한가 (plan P-1)

백테스트 엔진은 셋업 탐지(analysis) → 승인(decision) → 가상 체결(execution)을 **전부 호출**한다.
이것을 `analysis/` 에 두면 `analysis → execution` import 가 필요해지고, 그것은 tasks.md P0-2 가
명시적으로 금지한 바로 그 규칙 위반이다.

`apps/` 에 두는 대안도 검토했으나 백테스트는 CLI 로도 웹으로도 실행되므로 양쪽에서 중복된다.

## 하지 않는 것

- 지표·구조물 계산 (→ `analysis`)
- 손절/익절/수량 확정 (→ `decision`)
- 주문 전송 (→ `execution`)
- HTTP 라우팅·스케줄 등록 (→ `apps`)
